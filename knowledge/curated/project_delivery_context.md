# 海外智能座舱语音项目角色分工与交付边界

## 文档定位

本条目是对内部项目背景材料的脱敏摘要，用于理解数据和测试工作的业务上下文。它不包含公司名称、人员姓名和商业合同细节，也不能替代正式合同、Statement of Work 或项目责任矩阵。

## 典型协作角色

| 角色 | 主要职责 | 质量数据关注点 |
|---|---|---|
| 语音技术与项目牵头方 | 提供离线 ASR、TTS、NLU 等底层能力，协调项目计划与技术质量 | 模型版本、能力边界、缺陷闭环和跨团队风险 |
| SDK 集成与交付方 | 封装端侧语音 SDK，并承担合同交付与集成协调 | SDK 版本、接口兼容、集成测试和交付状态 |
| 数据与测试支持方 | 数据构造、采集、标注、质检，以及 ASR/NLU/TTS 和端到端测试 | 数据版本、测试范围、指标口径、问题证据和复测结果 |
| 车企应用集成方 | 对接车控、导航、多媒体等业务接口并实现应用层体验 | Domain/Intent/Slot 覆盖、真实车辆场景和用户体验 |

## 对质量 Agent 的含义

1. 结论必须标明数据版本、语言、Domain 和来源范围，避免不同团队使用不同口径。
2. 底层模型问题、SDK 集成问题和应用接口问题不能仅凭 ASR 文本差异自动归因。
3. Agent 可以发现异常、聚合证据和生成变更建议，但不能替代项目责任认定。
4. 复测应关联原问题、修复版本、测试环境和结果，才能形成可审计闭环。
5. 本项目当前数据只覆盖语音质量分析的一部分，不代表完整的合同验收结论。
